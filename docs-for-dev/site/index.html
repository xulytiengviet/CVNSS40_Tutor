I. Dùng Plugin trong ChatGPT

Điều kiện: tài khoản hoặc workspace cho phép kết nối MCP tùy chỉnh. Tên menu có thể khác theo phiên bản giao diện và quyền tài khoản.

  1. Chuẩn bị địa chỉ MCP

    Dịch vụ được cấu hình trong kho mã:

    https://cvnss40-mcp.onrender.com/mcp

    Đây là địa chỉ dịch vụ, không phải endpoint của GitHub Pages. Trang hướng dẫn không theo dõi tình trạng hoạt động trực tiếp.

  2. Kết nối hoặc cập nhật plugin hiện có

    Trong ChatGPT, mở phần quản lý Plugins / Apps / Connectors và tìm chức năng thêm MCP tùy chỉnh. Nếu đã có CVNSS4.0 Knowledge Hub, mở cấu hình của nó thay vì tạo trùng. Nhập URL trên, chọn Streamable HTTP nếu giao diện yêu cầu.

    Bản dịch vụ này công khai, chỉ đọc, không OAuth: chọn No authentication nếu đó đúng là cấu hình máy chủ bạn dùng. Không gửi ghi chú riêng, mật khẩu hoặc hồ sơ cá nhân.

  3. Cài kỹ năng hướng dẫn khi giao diện hỗ trợ

    Tải gói kỹ năng v0.2.0. Gói chứa hướng dẫn và tài liệu tri thức; gói mặc định không có kết nối MCP. Nếu giao diện hỗ trợ nhập gói kỹ năng, nhập ZIP và giữ kết nối MCP đã cấu hình. Nếu không có chức năng nhập ZIP, bạn vẫn dùng trực tiếp công cụ qua kết nối MCP.

    Người quản trị muốn tạo ZIP kèm kết nối: python scripts/build_cvnss_chatgpt_plugin.py --mcp-url https://cvnss40-mcp.onrender.com/mcp. Chỉ làm sau khi xác minh máy chủ; đóng gói không tự triển khai hay cài plugin.

  4. Nạp danh sách công cụ

    Lưu kết nối, cho phép sử dụng theo giao diện và chọn Refresh / làm mới công cụ. Mã nguồn v0.2.0 cung cấp 7 công cụ. Nếu máy chủ chỉ có 6, phiên bản đó chưa có cvnss_knowledge; cần cập nhật máy chủ trước rồi làm mới kết nối.

  5. Thử phép chuyển đổi đầu tiên

    Mở cuộc trò chuyện, chọn plugin trong danh sách công cụ hoặc bằng @ nếu giao diện hỗ trợ. Gửi:

    Gọi cvnss_convert với text="Tiếng Việt", mode="cqn".
Cho biết kết quả cvss từ công cụ, không tự suy đoán.

    Kết quả kiểm thử tham chiếu: cvss = "Tizb Vidf". Tiếp theo, hỏi: “Gọi cvnss_sources, cho biết nguồn nào chưa nhập toàn văn.”

II. Kết nối bằng MCP

MCP là giao thức để ứng dụng AI khám phá và gọi công cụ. Dùng trình khách MCP hoặc Inspector; mở /mcp bằng trình duyệt không phải phép thử đầy đủ.

  1. Chọn máy chủ có sẵn hoặc chạy cục bộ

    Với máy chủ có sẵn, chuyển đến bước 3. Để tự chạy: cài Git, Python 3.11–3.14 và Node.js (khuyến nghị 22 LTS), rồi mở terminal:

    git clone https://github.com/xulytiengviet/CVNSS40_Tutor.git
cd CVNSS40_Tutor
python -m venv .venv
.venv/bin/python -m pip install "mcp>=1.26.0,<2.0.0"
.venv/bin/python -m cvnss_hub.mcp_server --http --port 8000

    Trên Windows, thay python đầu tiên bằng py và .venv/bin/python bằng .venv\Scripts\python.exe. Giữ terminal máy chủ đang chạy.

  2. Hoặc dùng stdio cho ứng dụng cục bộ

    Trong trình khách hỗ trợ stdio, đặt lệnh là đường dẫn tuyệt đối tới Python của venv; tham số ["-m", "cvnss_hub.mcp_server"]; thư mục làm việc là kho mã. Chế độ stdio không có URL. Tên trường cấu hình tùy trình khách.

  3. Kết nối Streamable HTTP

    Mở terminal khác và chạy Inspector:

    npx --yes @modelcontextprotocol/inspector@latest

    Trong Inspector, chọn Streamable HTTP và Connect tới http://127.0.0.1:8000/mcp khi chạy cục bộ, hoặc https://cvnss40-mcp.onrender.com/mcp khi dùng dịch vụ từ xa. ChatGPT web cần HTTPS hoặc tunnel được hỗ trợ, không dùng localhost trực tiếp.

  4. Khám phá rồi gọi công cụ

    Chọn List Tools cvnss_self_test với tham số {}. Kỳ vọng ok: true, tests: 23, failures: []. Sau đó gọi cvnss_convert với:

    {"text": "Tiếng Việt", "mode": "cqn"}

    mode mô tả định dạng đầu vào; kết quả trả các dạng cqn, cvn và cvss.

  5. Kiểm tra nguồn và giới hạn

    Gọi cvnss_sources({}), rồi cvnss_knowledge({"topic":"concepts"}) nếu máy chủ có công cụ này. Giữ nguyên nhãn bằng chứng và trạng thái duyệt khi dùng kết quả để trả lời. Khi giải mã, gọi cvnss_inspect để xem các ứng viên.

III. Tích hợp REST API

REST nằm trong máy chủ DeepTutor tại /api/cvnss4/*, áp dụng xác thực của DeepTutor. Dịch vụ Render độc lập chỉ phục vụ MCP và /healthz; không cung cấp các REST route bên dưới.

  1. Chuẩn bị máy chủ DeepTutor

    Người quản trị cần cài và khởi động DeepTutor theo hướng dẫn môi trường. Lấy địa chỉ máy chủ, ví dụ http://127.0.0.1:8001 khi chạy tại máy mình, rồi xác minh route trong OpenAPI của instance đó.

  2. Xác thực theo cơ chế máy chủ

    Đăng nhập DeepTutor bằng tài khoản của bạn. Ví dụ dưới dùng phiên trình duyệt cùng origin đã đăng nhập; không giả định có API key hay Bearer token dùng chung. Nếu dùng curl hoặc ứng dụng khác, làm theo cơ chế xác thực được cấu hình trên máy chủ và bảo vệ thông tin phiên.

  3. Gọi API chuyển đổi

    Mở Developer Tools Console ngay trên trang DeepTutor của bạn, kiểm tra đoạn mã rồi chạy:

    const response = await fetch('/api/cvnss4/convert', {
  method: 'POST',
  credentials: 'same-origin',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({text: 'Tiếng Việt', mode: 'cqn'})
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
console.log(await response.json());

    Kỳ vọng: {"cqn":"Tiếng Việt","cvn":"Tizb Vidf","cvss":"Tizb Vidf"}. Đoạn mã phải chạy ở origin DeepTutor, không chạy trên trang GitHub Pages này.

  4. Tra cứu tri thức theo chủ đề

    const response = await fetch('/api/cvnss4/knowledge?topic=limitations', {
  credentials: 'same-origin'
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
console.log(await response.json());

    Đọc các trường notice, evidence_type, review_status và source_refs. Dùng /api/cvnss4/sources để đối chiếu ID nguồn với URL.

  5. Xử lý lỗi trước khi hiển thị kết quả

    401/403: kiểm tra phiên và quyền. 404: kiểm tra đúng máy chủ và phiên bản. 422: tham số chưa hợp lệ. 503: Oracle không sẵn sàng, có thể thiếu Node.js. Không coi phản hồi lỗi là kết quả chuyển đổi.

Cách đọc một mục tri thức

evidence_type cho biết đó là nguồn gốc, hành vi thực thi, thực nghiệm, đề xuất hay chưa kiểm chứng. review_status là trạng thái duyệt riêng; một đề xuất đã duyệt vẫn là đề xuất.

Chỉ gọi một mục là “đã duyệt” khi có nguồn, vị trí trích dẫn, người duyệt và ngày duyệt; phát biểu từ nguồn gốc cần cả trích đoạn. Xem dữ liệu gốc, JSON Schema và đề xuất chuẩn hóa.

Trợ giúp

Kiểm tra đúng chỗ

Không tìm thấy chức năng thêm plugin hoặc MCP?

Kiểm tra quyền tài khoản, chính sách workspace và phiên bản giao diện. Tìm hướng dẫn kết nối MCP của nhà cung cấp. File ZIP không tự mở quyền hoặc cài một máy chủ.

Máy chủ có 6 công cụ, thiếu cvnss_knowledge?

Máy chủ có thể còn chạy mã cũ. Người quản trị triển khai v0.2.0, sau đó bạn làm mới danh sách công cụ trong plugin và mở cuộc trò chuyện mới. Trong lúc chờ, đọc tài liệu tri thức đi kèm ZIP.

GET /mcp trả lỗi, hoặc trình duyệt không hiện trang?

MCP cần khởi tạo giao thức và gọi công cụ bằng trình khách tương thích. Dùng Inspector để kiểm tra. /healthz chỉ cho biết phản hồi sức khỏe, chưa chứng minh phép chuyển đổi hoạt động.

REST trả 404, 401 hoặc 403?

Không gọi /api/cvnss4/* trên GitHub Pages hoặc máy chủ MCP Render độc lập. Dùng máy chủ DeepTutor đã bật route và xác thực phiên người dùng. Kiểm tra đúng origin và cấu hình quyền.

Lỗi 421 Invalid Host / 403 Invalid Origin / 429?

Với 421 hoặc lỗi Origin, đối chiếu hostname và origin của reverse proxy với allowlist máy chủ. Với 429, đợi theo Retry-After và giảm tần suất. Không tắt bảo vệ Host/Origin để xử lý nhanh.

Hỏi toàn bộ tri thức nhưng chỉ nhận liên kết hoặc bản nháp?

Đó là giới hạn dữ liệu hiện có. linked_not_ingested là nguồn chưa nhập toàn văn. Muốn hỏi đáp toàn bộ tài liệu, cần thu thập đúng quyền, duyệt nội dung rồi kết nối kho RAG đã lập chỉ mục.
